# Implementation and UX review — 1.7

This review follows the owner's request to identify and fix drawbacks in the existing implementation. It uses code inspection and isolated fixtures. No live mailbox authentication, sending, password changes or private mail inspection is necessary.

## Confirmed issues and work plan

| Area                          | Evidence / consequence                                                                                                                                                                                           | Resolution and verification                                                                                                                                                          |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Polling lifecycle             | A rejected old poll reaches `onError` after stop/reconnect and can pause the new connection.                                                                                                                     | Ignore failures from an obsolete sweep epoch; cover stop and reconnect races.                                                                                                        |
| Local drafts                  | Emptying a previously saved composer skips autosave/close persistence and leaves the old content recoverable as a draft.                                                                                         | Persist deletion of the exact emptied draft; preserve unsaved content on disk errors.                                                                                                |
| Legacy drafts                 | Updating a legacy `profile:account` draft adds a second `:draftId` entry without removing its legacy copy.                                                                                                       | Migrate that entry on successful save, with one current draft returned.                                                                                                              |
| Settings writes               | Local-draft/preferences/forget mutate in-memory settings before a failed disk write.                                                                                                                             | Commit replacement maps only after protected persistence succeeds. Preserve unrelated live object references and existing uncertain-send safeguards.                                 |
| Attachment validation         | Send totals trust renderer sizes, and earlier files can upload before a later missing/changed file is discovered. | Attachment UX / lifetime      | Oversized or over-count selections can make a draft impossible to save. Restarted drafts discover missing file handles only after Send. Unused imported bytes remain in memory.                                  | Enforce count/size limits before adding, mark unavailable restored attachments, and release unreferenced handles when removed/discarded/sent. All fixes in the table are implemented. Validation: **228 tests passing in 19 files**, including the original send, SMTP, image, privacy and account-isolation regressions. TypeScript passes. Package and visual verification are recorded in TEST-REPORT.md.

Additional confirmed issues fixed during the review:

- A mailbox error or token renewal finishing after Forget could persist the old secret again and resurrect the forgotten account. Transport operations now carry a session generation, and disconnected sessions cannot write token/pause state or continue with follow-up requests. Regression tests inspect both in-memory and protected on-disk profiles after these races.
- Rejected connection/Forget operations no longer reset the polling baseline; only completed operations reset and wake synchronization.

- A queued request could outlive its otherwise healthy access token. It can now renew once **before the first mail API dispatch** and rejoin the shared pacer. A short token, failed renewal, server rejection or ambiguous network result still stops without retrying a mail operation.
- A send blocked locally before its API request was issued could leave a permanent uncertain-send marker. A typed pre-dispatch failure now clears only that marker; requests actually dispatched retain the existing conservative protection.
- The global check-time caption could report a different mailbox's polling time. Check times are now scoped to each mailbox.
- A removed source mailbox could fall back to the first available mailbox during a state transition. All rows now carry explicit source identity, and missing sources fail closed. Global reply controls also require detail from the current selection.
- Starting a search from Unread left that tab selected although the provider search endpoint does not accept the same status parameter. Search now resets the view filter to All; custom Zoho search expressions remain supported. Contract: [Zoho search API](https://www.zoho.com/mail/help/api/get-search-emails.html).
- Enter in the link text field could implicitly submit the compose form. Enter now applies the link; Escape closes only the link editor. Nested dialogs similarly handle Escape only at the topmost dialog.
- Malformed provider list entries could flow into invalid identifiers and repeated UI failures. Required folder/message identifiers and list entries now stop the connection at that boundary. Unusable dates are normalized safely.
- Remote tracking images caused an unnecessary authenticated attachment-metadata read. Only actual embedded references request that metadata; remote images remain blocked.
- A JSON attachment containing a `status.code` error field could be mistaken for a provider rejection. A response explicitly marked as an HTTP attachment is now treated as file content.
- Recipient chip separators are normalized before API submission, so a committed trailing comma or semicolon never becomes an empty wire recipient.

Unconfirmed provider behavior is not labelled a defect. In particular, an older empty unscoped list probe also used an explicit threaded filter; it does not prove that today's filter-free All mail request is broken. The recipient Escape handler was inspected and already stopped propagation correctly; it was not reported as a bug.

## Validation detail

Regressions exercise delayed rejected polls after reconnect/stop, queued-token expiry, zero-dispatch sends versus ambiguous sends, failed protected-storage writes, legacy draft migration, out-of-order draft writes/clearing/discard, forged attachment sizes, missing later attachments before any upload, same-size file edits, unavailable restored handles, operation locks, streamed size enforcement, recipient entry/removal/editing, pending-file exit protection, signature countdown locking, link-keyboard behavior, notification folder routing, mailbox check times, consumed bulk selections, missing dates, selection-bound reply controls, malformed list entries and blocked remote-image requests. No real mailbox credentials or messages are used as fixtures.

## Retained design boundaries

- No automatic startup sign-in or retry after an authentication/security/rate-limit failure.
- Uncertain send outcomes remain guarded by the durable submission ledger; no speculative automatic resend.
- Received HTML stays in an isolated, script-free sandbox. A potential full-height reader improvement must not weaken that boundary merely to remove nested scrolling.
- No whole-thread deletion, subject-based conversation guessing, subscription changes, new credentials or provider API assumptions are introduced by this review.
