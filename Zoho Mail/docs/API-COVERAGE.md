# API coverage and implementation boundaries

Research checked against official Zoho documentation on 2026-10-27. API requests are constructed only in `desktop/zoho.ts` and `desktop/transport.ts`. The renderer sends validated operations, never arbitrary remote URLs. Numeric IDs remain strings; JSON-bigint prevents precision loss from unquoted server IDs.

## Mail client capabilities

## API families reviewed, deliberately outside this mail client

The [complete API index](https://www.zoho.com/mail/help/api/) also contains organization, domain, group, user, mail-policy, logs, anti-spam administration, tasks, notes, bookmarks and thread-wide mutation APIs. They are documented capabilities, not promises that every free organization can use every endpoint.

- Organization/domain/user/group administration remains in Zoho Admin. No admin scopes are requested. DNS, subscriptions, catch-all and user creation are outside this client.
- Tasks, notes, bookmarks, projects and group collaboration would turn a small mail client into another suite. No placeholder buttons are presented for them.
- Mail account configuration changes, forwarding, vacation replies, security policy and identity changes are not exposed. Some are plan-restricted, and they are not needed to replace the mail view.
- Whole-thread actions are not substituted for selected-message actions. There is no separate conversation-folding UI yet; each message can be read and replied to with its original reference.
- Permanent deletion, folder emptying, folder deletion, label deletion and remote signature editing are not exposed in this release.
- No invented contact/calendar synchronization API, IMAP/SMTP bridge, cookie scraping, mobile-app impersonation, or undocumented private API.
- Complex HTML composition, inline images, automatic forwarding of original attachments, offline mailbox caching, and push notifications are not implemented. These are client scope decisions, not blanket claims that Zoho cannot support them.

## Authentication, limits and response handling

[Self Client](https://www.zoho.com/developer/oauth/self-client/overview.html) authorization codes are exchanged at the selected Accounts host's `/oauth/v2/token`. A refresh token is used only on explicit Connect. [OAuth guide](https://www.zoho.com/mail/help/api/using-oauth-2.html).

The documented Mail API policy is [30 requests per minute](https://www.zoho.com/mail/help/adminconsole/rates-and-limits.html). The client serializes all profiles through one pacer with 2.6 seconds between starts (under 24/minute). Search does not fire on every keystroke. There are no retries or periodic collectors. Failed authentication, redirects, malformed bodies, rejection, rate limits and uncertain network results pause the affected profile. Queue entries recheck connection state before execution.

Use only account IDs returned by the matching authorization. Provider error payloads are not echoed to the UI or logs because they may contain confidential data. APIs and free-account entitlement remain unverified against live production accounts; fixture tests verify request construction and error behavior.
