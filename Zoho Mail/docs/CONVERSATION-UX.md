# Conversation reading: research and decisions

Reviewed 2026-10-28 for Fluent Mail 1.6.0. This research concerns presentation, not changes to Zoho's conversation identity or mailbox permissions. The owner confirmed 1.5 now displays both conversation history and incoming images, but could not reliably identify the latest message.

Do not introduce subject-based grouping or claim an order that this source does not document.                         |

These are documented product behaviors, not fresh sign-in tests of private accounts. No private messages or competitor screenshots are reproduced. Our choices below are design judgments based on these findings, rather than a claim that one layout is universally best.

## Fluent Mail 1.6

- Default to **Newest first**, putting the most recent message within immediate reach. An always-visible **Conversation order** control offers **Oldest first** and remembers the choice locally; it adds no account setting or API scope.
- Label the newest card **Latest** independently of its unread status and its position. Older cards say **Earlier**. A separate **Unread** label prevents the common assumption that blue or bold means newest.
- Show **Message N of M** in chronological sequence when the complete conversation is loaded. Under partial pagination, say **Earlier message** instead of inventing a starting position. Do not call the oldest loaded page the original email.
- Show clear local timestamps on every card, with full date/time/time-zone information available on the timestamp. Missing timestamps are explicitly unavailable rather than a misleading date.
- Keep a compact, sticky conversation bar that states the current order and whether the reader is viewing the latest or an earlier message. **Go to latest** opens, activates and scrolls to the newest card without changing the order or re-fetching an already loaded body.
- Open the latest message when opening a conversation row. Deliberately opening an older header makes that message the reply target. Per-card replies remain tied to their exact message; an earlier-message notice makes the global toolbar target clear.
- Collapse history initially; keep **Expand all** and offer **Collapse earlier messages**. Reversing order preserves bodies, expansion and reply selection and makes no new provider request.
- Request thread summaries explicitly by descending date, so the first bounded page contains the newest messages. Continue loading older summaries only on request. Keep exact IDs, account isolation, cached bodies, authenticated raster-image display and existing first-failure handling.

## Acceptance checks

Cover both order choices, remembered preference, latest-vs-unread distinction, sequence numbers independent of display order, partial-history labels, opening an old folder row with newer cross-folder replies, older-message reply targets, Go to latest, cached bodies, refresh/arrival updates and failures. Inspect the packaged app with fictional mail. Export the actual application window for GitHub; no real inbox data is suitable for a public screenshot.
